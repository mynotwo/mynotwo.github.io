01 / The failure worth solving

Passing examples did not identify the rule.

Two example tables fit an inferred scheduling formula. A later document revision specified a different dependency: both prerequisites must be ready before the service window starts.

The examples supported this reading, but did not establish it as the governing rule.

Specified in the revised source

Both prerequisites, then the service window

The revised formula explicitly includes A. The implementation and expected outputs have to follow that change.

02 / The engineering approach

Keep the rule, its authority, and its consequences connected.

The workflow separates what the source says from what the agent infers. That distinction stays attached as the rule becomes code and as the source changes.

  1. Preserve the source

    Retain document revisions, normalized source-block hashes, and referenced asset hashes so a decision can be traced back to the evidence it used.

  2. Expose the interpretation

    Write down the fields, dependency relations, formulas, branches, and open questions before treating the document as an executable specification.

  3. Challenge the rule

    Use hand-checkable cases and an independently built reference model. Inject plausible wrong formulas and check that a case or invariant rejects them.

  4. Trace a revision

    Connect source blocks to rules, operations, code, and cases. When the source changes, mark dependent judgments stale and rerun the affected checks.

An explicit state machine helps expose a missing prerequisite. It cannot decide which business rule is authoritative.

How are inferred and authorized rules distinguished?

The case workflow records unresolved, AI-inferred, evidence-derived, user-answered, and author-answered interpretations. These labels describe different sources of support; they are not a confidence score or an automatic promotion ladder. An example matching a rule does not give that example authority to define policy.

What changes when a source revision arrives?

Source-block content, revision identity, and asset bytes determine freshness. A change makes dependent judgments stale through the source → rule → operation → case links. The review unit is the affected rule and its downstream outputs, rather than the entire document.

What does verification establish—and what does it leave open?

Regression cases, reconciliation, mutation checks, and replay diffs can test whether code follows an interpretation. They cannot authorize a consequential choice that the source leaves undefined. That decision remains open until an appropriate owner or source resolves it.

Evidence-grounded Task World Models

Represent the entities, states, relations, transitions, constraints, and unknowns an agent needs for a task. Attach provenance and evidence status to each element instead of silently completing gaps.

The proposed evaluation compares direct text-to-action with an explicit model under missing, contradictory, and stale evidence. The outline describes the research design; it does not report measured improvements.
